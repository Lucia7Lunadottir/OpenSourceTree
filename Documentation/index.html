OpenSourceTree

Git GUI-клиент, вдохновлённый SourceTree, написанный на Python с использованием PyQt6. Поддерживает тёмную тему Equestria OS Purple, 10 языков интерфейса и полный набор функций для работы с Git-репозиториями.

Python 3 PyQt6 Git NumPy Pygments GPL-3.0

Основные возможности

🌿 Управление ветками

Создание, переименование, удаление, merge, rebase. Отображение ahead/behind относительно upstream.

📜 История коммитов

Топологически упорядоченный граф коммитов с lane-визуализацией. Поиск по сообщению и автору.

📁 Working Copy

Stage/unstage файлов по отдельности или всех сразу. Коммит с поддержкой amend.

🔀 Remote-операции

Fetch, pull, push со стриминговым прогрессом. Force-push с защитой --force-with-lease.

🔑 Аутентификация

SSH-профили с автоматическим SSH config. HTTPS через ASKPASS-скрипт. Поддержка 4 провайдеров.

📦 Git LFS

Полная поддержка: список файлов, track/untrack, pull/push/fetch, prune.

✂️ Split Commit

Разбивка одного коммита на несколько батчей файлов с переписыванием истории.

⚔️ Конфликты

Разрешение merge-конфликтов: ours / theirs / mark resolved. Abort/continue для merge и rebase.

⚡ Async / Workers

Все блокирующие git-операции выполняются в отдельных потоках через QThreadPool.

🔵 GitWorker

Выполняет одиночный вызов fn(*args) в потоке. Эмитирует result, error, finished.

🟢 StreamingWorker

Итерирует генератор fn(). Каждая строка вывода — сигнал progress_text(str).

🟡 BatchWorker

Выполняет список операций последовательно в одном потоке. Используется для multi-step действий.

Пример использования GitWorker
def _do_commit(self, message: str):
    worker = GitWorker(self.repo.commit, message)
    worker.signals.result.connect(self._on_commit_done)
    worker.signals.error.connect(self._on_error)
    QThreadPool.globalInstance().start(worker)

def _do_fetch_streaming(self, remote: str):
    worker = StreamingWorker(self.repo.fetch_streaming, remote)
    worker.signals.progress_text.connect(self.log_label.setText)
    worker.signals.finished.connect(self._on_fetch_done)
    QThreadPool.globalInstance().start(worker)
⚠️
Для multi-step операций (Split Commit, Safe Reset) используется write lock — мьютекс, который блокирует параллельные git-вызовы до завершения всей операции.

🖥️ GitRunner

Низкоуровневая обёртка над subprocess. Файл: app/git/runner.py.

def __init__(self, repo_path: str)
Создаёт runner для конкретного репозитория. Устанавливает cwd для всех дочерних процессов. Вызывает _build_env() для подготовки окружения с SSH и ASKPASS переменными.
def run(self, args: list[str], input: str | None = None, timeout: int | None = None) → str
Запускает git *args, возвращает stdout.decode(). При ненулевом коде возврата бросает GitError с stderr.
Параметры:
input — строка, передаваемая в stdin процесса
timeout — таймаут в секундах (по умолчанию 60 с)
def run_bytes(self, args: list[str], timeout: int | None = None) → bytes
Аналог run(), но возвращает сырые байты. Используется для команд, работающих с бинарными данными (например, git cat-file -p для LFS).
def run_streaming(self, args: list[str]) → Iterator[str]
Запускает git-процесс и yielding'ует строки stdout по мере их появления. Используется в fetch/pull/push для real-time прогресса в UI.
def run_in_terminal(self, args: list[str]) → None
Открывает интерактивный эмулятор терминала (konsole → xterm → alacritty → kitty → foot) для выполнения git-команды с интерактивным вводом (SSH passphrase).

📚 GitRepo — главный API

Высокоуровневая абстракция над git. Файл: app/git/repo.py (~950 строк).

ℹ️
Конструктор: GitRepo(path: str) — принимает путь к директории репозитория. Создаёт внутренний GitRunner(path). Метод класса GitRepo.is_git_repo(path) проверяет, является ли директория git-репозиторием.

Операции с коммитами

get_commits(skip=0, limit=200, branch="", search="") → list[CommitRecord]
Загружает историю коммитов в топологическом порядке. Применяет graph_layout. search фильтрует по сообщению и автору.
get_commit_detail(hash: str) → CommitRecord
Детальная информация о коммите включая полное тело сообщения.
get_commit_files(hash: str) → list[FileStatusEntry]
Список файлов, изменённых в данном коммите.
get_diff(hash: str, file_path="") → str
Возвращает diff коммита. Если file_path указан — diff только для этого файла.
commit(message: str, amend: bool = False) → str
Создаёт коммит из staged файлов. При amend=True изменяет последний коммит.
cherry_pick(hash: str) → None
Cherry-pick указанного коммита на текущую ветку.
split_commit(sha: str, batches: list[list[str]], message: str) → None
Разбивает коммит sha на несколько коммитов по батчам файлов. Использует write lock. Работает как для HEAD, так и для коммитов в истории.
safe_reset_hard(hash: str) → str
Безопасный reset: сохраняет незакоммиченные изменения в stash перед git reset --hard. Возвращает метку stash.

Staging (индекс)

get_working_copy_status() → tuple[list[FileStatusEntry], list[FileStatusEntry]]
Возвращает кортеж (staged_files, unstaged_files). Парсит git status --porcelain=v1.
stage_file(path: str) / stage_files(paths: list[str]) / stage_all()
Добавляет файл(ы) или все файлы в индекс (git add).
unstage_file(path: str) / unstage_files(paths: list[str]) / unstage_all()
Удаляет файл(ы) из индекса (git reset HEAD).
get_working_copy_diff(path: str, staged: bool) → str
Diff файла в рабочей копии. staged=True → git diff --cached, иначе git diff.
safe_discard_files(paths: list[str]) → str
Безопасный discard: сохраняет файлы в stash с меткой, затем удаляет из рабочей копии. Изменения восстанавливаемы через stash pop.
stage_hunk(patch: str) → None
Применяет патч частично (git apply --cached) для stage отдельных hunk'ов.

Ветки

get_branches() → list[BranchInfo]
Возвращает все локальные и удалённые ветки с ahead/behind, tracking.
create_branch(name: str, from_ref: str = "HEAD") → None
Создаёт новую ветку от from_ref и переключается на неё.
merge(branch: str, no_ff: bool = False, squash: bool = False) → None
Выполняет merge ветки branch в текущую. Поддерживает флаги --no-ff и --squash.
rebase(branch: str) → None
Выполняет rebase текущей ветки поверх branch.

Remote-операции

fetch_streaming(remote="", prune=False, tags=True) → Iterator[str]
Стриминговый fetch с real-time прогрессом. prune=True удаляет устаревшие remote-ветки.
pull_streaming(remote="", branch="", rebase=False) → Iterator[str]
Стриминговый pull. rebase=True использует git pull --rebase.
push_streaming(remote="", branch="", force=False, tags=False) → Iterator[str]
Стриминговый push. force=True использует --force-with-lease (безопасная force-push).
💡
Нестриминговые версии (fetch, pull, push) также существуют и возвращают str — используются реже, в основном для тестирования.

Stash

stash_save(message="", include_untracked=True) → None
Сохраняет изменения в stash. include_untracked=True добавляет неотслеживаемые файлы (-u).
stash_pop(index: int = 0) / stash_apply(index: int = 0) / stash_drop(index: int = 0)
Pop восстанавливает и удаляет stash. Apply — только восстанавливает. Drop — только удаляет.

Теги

create_tag(name: str, ref="HEAD", message="") → None
Создаёт тег. Если message задан — annotated tag (-a -m), иначе lightweight.
push_tag_streaming(name: str, remote="origin") → Iterator[str]
Push тега на remote с прогрессом.
delete_remote_tag(name: str, remote="origin") → None
Удаляет тег с remote (git push remote :refs/tags/name).

Конфликты

get_conflicted_files() → list[str]
Список файлов с конфликтами (статус U, AA, DD, AU, UA и т.д.).
resolve_ours(path: str) / resolve_theirs(path: str)
Разрешение конфликта в пользу нашей или их версии файла.
is_merging() / is_rebasing() / is_cherry_picking() → bool
Проверяет текущее состояние репозитория по наличию служебных файлов Git.
abort_merge() / abort_rebase() / abort_cherry_pick()
Прерывает текущую операцию слияния/rebase/cherry-pick.

Git LFS

lfs_is_enabled() → bool
Проверяет, инициализирован ли LFS в репозитории (наличие .gitattributes с lfs-фильтрами).
lfs_list_files() → list[LfsFileEntry]
Список файлов под управлением LFS с их OID и размерами.
lfs_pull(paths: list[str] = []) / lfs_fetch(remote="", all_=False) / lfs_push(remote="origin") → Iterator[str]
Стриминговые LFS-операции. lfs_pull без аргументов загружает все LFS-файлы.

🕸️ Алгоритм Graph Layout

Файл: app/git/graph_layout.py. Визуализация истории в виде DAG-графа с lane'ами.

Принцип работы

  1. Коммиты принимаются в топологическом порядке (новые первые)
  2. Для каждого коммита определяется lane: либо переиспользуется lane первого родителя, либо выделяется новый
  3. Отслеживаются open_lanes — lane'ы, ожидающие продолжения (родитель ещё не встречен)
  4. Записываются соединения: от каких lane'ов приходят и к каким уходят линии
  5. Когда последний ребёнок коммита встречен — lane освобождается (MAX_LANES = 32)
  6. Результат: каждый CommitRecord получает lane и LaneData
LaneData — структура соединений
@dataclass
class LaneData:
    connections: list[tuple[int, int]]  # (from_lane, to_lane) — линии между строками
    active_lanes: list[int]            # lane'ы, проходящие сквозь эту строку
    merge_lanes: list[int]             # входящие lane'ы для merge-коммитов
ℹ️
NumPy используется для эффективного отслеживания массива open_lanes как бинарного вектора длиной MAX_LANES=32. Это позволяет быстро найти свободный lane (np.argmin) и проверить занятость.
